How a pull request works

A branch is a named line of work. A pull request (PR) is a GitHub page that says: “please take the commits on this branch and add them to main.” You read the diff, comment, then merge or close.

The three practice PRs

1. This page — a real, useful change. Open it, read Files changed, leave a comment if you want, then merge with Squash and merge. Afterward, delete the branch when GitHub offers.

2. A one-line AGENTS.md note — another developer’s tiny docs tweak. Merge this one with Create a merge commit so you can see how that differs from squash.

3. A junk file — do not merge. Click Close pull request, then delete the branch. That is how you reject work.

On GitHub (no terminal)

  1. Open github.com/az9713/cursor-origin/pulls.
  2. Click a PR titled [PRACTICE].
  3. Conversation is the discussion. Files changed is the actual diff. Commits lists each commit.
  4. On Files changed, click Review changes → Comment or Approve → Submit review.
  5. Merge or Close. That is the whole loop.

On your machine after a merge

GitHub has the new main. Your laptop does not until you update it. In a terminal, from this repo:

git checkout main

git pull origin main

That downloads the merged work. You do not need Origin (cursor) for this lesson. PRs live on GitHub only.
